# Portcullis Templates — Claude Code Instructions

## Project Overview

Default app marketplace for Portcullis. Contains 45 app templates with manifest.yaml + compose.yml.

## Layout & tooling

- `schema/manifest.schema.json` — manifest JSON Schema (2020-12); keep in sync with the Hub's `validateManifest` and the docs manifest reference
- `tests/validate.py` — schema + repo rules (run `python3 tests/validate.py`; needs `tests/requirements.txt`). Add new rules here, with a contributor-facing hint. `check_hub_rules` mirrors the Hub's discovery refusals (portcullis-hub `internal/templates/coreref.go`: compose key allowlist, Traefik key / attribute / middleware allowlists, ASCII and lowercase keys, references to own services / middlewares only, reserved core service / DNS / network / volume / Traefik names (`grafana` included — the grafana template's service is `dashboards`), no interpolation in names or `traefik.*` values, no `forward-auth-ext` / `portcullis-auth-ext` / `portcullis-oauth2-`); keep its lists in sync with the Hub's (a template CI accepts must not be skipped by the Hub)
- `tests/compose-config.sh` — `docker compose config -q` per template with dummy generated env
- `.core-ref` — core ref CI tests against (contracts §1); `.github/dependabot.yml` must list every template dir
- CI: `lint.yml` (all PRs incl. forks, no secrets), `test-apps.yml` (integration for every PR incl. forks; core is public and cloned without a token, no job references a secret; `.core-ref` read from the PR base; image caches are written only by `fetch-core` (infra) and `app-images` (per-app, push to main only, list from `tests/app-images.sh`); `test` runs template code with no secrets, saves no cache, strips names from loaded tarballs and binds every image by a pinned-digest pull; boots core like core's own CI (`ci.yml` job e2e): `portcullis init --env-only` generates every secret — never set core secrets in the workflow env, it overrides `.env` — `vault init`, `pki setup`, `config apply --bundle-only`, every core service but the Hub (every core service with a `build:` — enroll, group-gate, domains — built from core; their base images are in the infra image list), production Keycloak `start`, then `keycloak configure` (creates the invite IdP, needs enroll running) + `oidc register`; asserts the invite IdP exists and forward-auth redirects to `auth.<domain>`; tests/lib.sh reads core credentials (Keycloak/LLDAP admin only) from the env or core's `.env`, no defaults. Sign-in is passkey-only: no user password, no direct grant, so shell tests cannot get a user session — they assert the unauthenticated side and header trust (only `grafana.sh` exercises forward-auth through Traefik); after each shell test `tests/e2e/app_signin.py` (Playwright + CDP virtual authenticator, `tests/e2e/requirements.txt` hash-pinned, Chromium cached by job `e2e-browser` on main only) signs e2eadmin/e2emember/e2eoutsider in through setup links, driven by the manifest's `tests.signin` (schema + validate.py `check_signin_test`; CONTRIBUTING.md "Sign-in test"): it registers the Keycloak clients and writes the group-gate policy itself (version read from core's group-gate.py), the workflow generates the app's random env once for both steps, adds every hostname as a Traefik alias on portcullis-proxy (public-DNS stand-in) and to /etc/hosts; `skip` only for public/custom/mtls, native-oidc + group_access false apps that let outsiders in mark `expected_fail.outsider` (until Hub Task 4b), gated apps never may; never weaken an app's access control (e.g. auto-provisioning) to make a check pass — mark it expected_fail instead; artifacts `e2e-<app>` on failure; dispatch `apps=all`), `docs-dispatch.yml` (push to main → `templates-updated` to portcullis-docs), `dependabot-automerge.yml` (workflow_run after Lint / Test Apps on `dependabot/**`, + dispatch `pr=<n>` with `dry_run`; never pull_request_target, never checks out PR code; logic in `.github/automerge/automerge.sh` — identical copy in core and Hub, keep in sync — tested by `.github/automerge/test.sh` (fake gh + fixtures, run in lint): only dependabot[bot]'s single commit from this repo, committed + signed by web-flow, with every push in the PR timeline by dependabot[bot] (unreadable timeline = refuse; threat model in the script header: write-access accounts can push to main anyway, so this stops mixed pushes, not collaborators) whose head SHA = the SHA both workflows passed on; patch/minor/digest-only → `gh pr merge --squash --match-head-commit`, then dispatches lint, test-apps (`apps=<dirs>`) and docs-dispatch on main (GITHUB_TOKEN merges start no push workflows; skipped while a run of it is queued/running on main — the concurrency group would cancel it); major or unknown type → label `major-update`, left open; pre-release → closed with a comment; red → one `update-failed` issue per app + jump (title `Update failed: <app>: <dep> <from> → <to>`), closed on merge; per-job permissions: decide read-only, `pr` contents+pull-requests write, `issue` issues write, `dispatch` actions write; Craft PRs not covered), `craft-releases.yml` (weekly + dispatch, `contents`/`pull-requests`/`actions: write`, GITHUB_TOKEN only: `tests/craft-releases.sh` bumps each Craft template's `${CRAFT_VERSION:-…}`/`${CRAFT_SHA256:-…}` to the storytold/<app> latest release once the GitHub asset digest, `SHA256SUMS.txt` and the download agree, one PR per app on `craft/<app>-<ver>`; such PRs start no pull_request CI, so the script dispatches Test Apps `pr=<n> apps=<app>` (its check attaches to the base commit, so the run is linked in the PR body) and Lint on the branch); a change to `tests/app-images.sh` re-tests all apps
- `CHANGELOG.md` — upgrade notes for changes that need admin action (e.g. group membership); keep it with the docs' upgrading page
- Contributor docs: `CONTRIBUTING.md`, `.github/pull_request_template.md`, `.github/ISSUE_TEMPLATE/`

## Critical Rules

- Every template MUST have `manifest.yaml` with a full `auth` section
- Compose files use `portcullis-proxy` external network (NOT `portcullis`)
- Frontend services: `networks: [default, portcullis-proxy]`
- Internal services (DBs, Redis): default network only
- Header-auth apps must accept identity headers (X-Forwarded-User etc.) only from Traefik: use the app's proxy allowlist with `${PORTCULLIS_TRAEFIK_IP:-172.31.250.2}` (core var, Traefik's static IP on portcullis-proxy). If the app has no allowlist, reject the header from other peers in the app's own web server (Firefly, Guacamole) or keep the app off portcullis-proxy behind a gate (CloudBeaver). Never trust `**` / `0.0.0.0/0`. Tests use `assert_traefik_only_trust` / `assert_spoofed_identity_rejected` (tests/lib.sh)
- Identity = LLDAP username, never email (core 427c0aa): LLDAP lets users edit their own email, Keycloak marks it unverified (`email_verified=false`), group-gate sends `X-Forwarded-User` = username and `X-Forwarded-Email` = email (display/notifications only). Header-auth apps key on X-Forwarded-User; OIDC apps key on `sub`/`preferred_username` and must never link accounts by email (Vaultwarden `SSO_SIGNUPS_MATCH_EMAIL: "false"`, GitLab `omniauth_auto_link_user = false`, LiteLLM email attribute → unsent claim, Immich `immich-lock-local-users`, Headscale `email_verified_required: true`). Apps that reject `email_verified=false` but accept it absent set `keycloak_clients[].email_verified_claim: false` (Hub attaches core's `email-unverified` scope instead of `email`) and must not request the `email` scope (Keycloak: `invalid_scope`; validate.py checks `*SCOPE*` env); only Vaultwarden needs it (checked upstream: Immich, GitLab, LiteLLM, Actual, Headscale, NetBird don't gate on the claim). Gates that reject foreign X-Forwarded-User must reject X-Forwarded-Email too. validate.py `IDENTITY_*` tables (and `REQUIRED_INIT_JOBS`: immich-lock-local-users, paperless-init, mealie-init) enforce this; add new apps' settings there
- Template contract v2 (contracts §3.1): every manifest sets `instances: multi` (`single` only for host-level uniqueness, with the reason in `auth.notes`; none today). Host-level resources are per instance: netbird's coturn keeps host networking but reads its STUN/TURNS ports and relay range from the manifest `ports:` (validate.py: a multi template's `network_mode_host` port keys must be used in compose), scrutiny gets only the disks listed in its Disk 1-8 settings as `devices:` (`:r`) with SYS_RAWIO (+ SYS_ADMIN via a select for NVMe) instead of `privileged` (refused for multi). Every router rule is ``Host(`${PORTCULLIS_HOST_<ROUTER>:-<sub>.portcullis.local}`)`` [`&& <path matchers>`], `<ROUTER>` = the host router's name (rule with Host() alone) upper-cased, `-`→`_`; own hostnames everywhere use that variable with the same default, manifest `urls`/redirect URIs `{{HOST_<ROUTER>}}`; client ids and groups via `${PORTCULLIS_OIDC_CLIENT_ID(_<KEY>):-…}`, `${PORTCULLIS_ACCESS_GROUP:-users_<app>}`, `${PORTCULLIS_ADMIN_GROUP:-admin_<app>}` (also in support files, through `environment:`); no `_` in Traefik names; services on portcullis-proxy reach each other only via `default`-only aliases (headscale-internal). validate.py enforces it; `tests/test_validate.py` unit-tests validate.py (run in lint)
- Volumes: `multi` templates declare no `name:` (the Hub's override names the default instance's `portcullis_<key>` — today's names — and others `portcullis_<id>-<key>`); `single` ones declare exactly `name: portcullis_<key>`. Never rename a volume key: it is the default instance's data volume name
- Files shipped with a template are mounted read-only as `./templates/<app-id>/<file>:<path>:ro` (every instance shares them) — relative paths resolve against the core checkout on the host, and the Hub copies the template dir to `<core>/templates/<app-id>/` before every `compose up` (CI copies this repo there). Never `./<file>` directly.
- Do NOT reference `./scripts/`. From `./certs/`, only `./certs/ca-bundle.crt:<path>:ro` may be mounted (the Hub-provided CA bundle); nothing else under `./certs/`
- Every `${VAR:?...}` (required) var in a compose file must be either a core var (e.g. `PORTCULLIS_DOMAIN`) or listed in the manifest `env:` with `generate: random` — the Hub only writes those into the per-app .env (tests/lib.sh mirrors this in CI)
- Images: explicit version tag + `@sha256:` index digest, never floating tags; don't bump DB majors; keep multi-image apps in lockstep (netbird management/signal, immich server/ML, guacamole/guacd) and note upstream upgrade paths in `auth.notes`
- Native-OIDC host-wide routers never use forward-auth, except a separately hosted static web client with no login of its own and no server data, listed in validate.py `GATED_CLIENT_ROUTERS` (which also requires it to stay gated): matrix's `element`. If the app can't restrict OIDC logins by group (GitLab CE, LiteLLM, Vaultwarden), gate only its login paths with a higher-priority `PathPrefix` router using `portcullis-auth@docker,portcullis-groups@docker` and set `group_access: true` (validate.py `LOGIN_GATES` guards gitlab/litellm/vaultwarden/paperless; never protect a password form or a setup wizard with a path router — Traefik's path matching differs from the app's (case, `//`, `/index.php`): such apps get no password login at all (nextcloud, wiki); Vaultwarden also needs `INVITATIONS_ALLOWED`/`SIGNUPS_ALLOWED` false, since email invitations create placeholder accounts the first SSO user with that email claims). SSO users get the least-privileged role
- Public share links go in `auth.public_access` (paths with one `{token}` segment + anchored `token_pattern`, `supporting` assets, `default_mode`, `enabled_by_default`), never as an ungated router in compose.yml: the Hub generates the public router (no forward-auth, identity headers stripped, one TLS tier per host). Header-auth apps with it list `auth.identity_headers`. `supporting` paths serve static files only (exact routes need `exact` + `justification`); login headers/cookies/query params go in `credential_headers`/`credential_cookies`/`credential_query`; core's public guard (group-gate `/public-guard`, policy file at the version core serves — `policy_version`, read from core's group-gate.py) refuses them and Authorization. CI's grafana test runs the real guard (`write_public_policy` in tests/lib.sh) — it needs a core with `/public-guard`. Researched lists: grafana (listed, on by default = nothing open until a share is listed), nextcloud (listed, on by default; native OIDC, so it only matters on hosts whose policy requires a client certificate), immich (all, off by default). Vaultwarden Send and Kanboard can't be scoped by path (see their notes)
- `auth.native_login` (`supported: true`, `allow_without_gateway`, `note`) is only for `method: custom` + `sso: false` (schema + validate.py): the Hub's per-app Sign-in setting then puts Portcullis sign-in in front of the app's own login (default; its override prepends `portcullis-auth@docker,portcullis-groups@docker`, group = `access_group`) or, if allowed, leaves the app's own login only (public@file). Compose never carries the gateway middlewares for custom apps; `group_access: true` on custom needs native_login. Plex is the case
- Native-OIDC apps configured at start: nextcloud (`setup.sh` before-starting hook: pinned user_oidc, secret via `--clientsecret-env` (never argv), uid = preferred_username, soft auto-provisioning off, group whitelist, every local account disabled = no password login, break-glass is occ; `cron.sh` maps admin_<id> to Nextcloud's admin group and re-disables local accounts), wiki (`wiki-init` SQL before boot: site URL + Guests stripped; `setup.py` GraphQL with its own API key: OIDC strategy, local strategy off, groups; the healthcheck passes only in that OIDC-only state, so Traefik routes nothing before), dokuwiki (`init.sh` in /custom-cont-init.d: locks down first (no auth backend, install.php gone), vendored oauth/oauthgeneric in `dokuwiki/plugins`, `json-mail` = preferred_username because the plugin keys accounts by mail, ACL; OIDC config written last). paperless (`paperless-init` (init.py) before boot, all volumes mounted: compatibility check + migrations under the data-dir lock, a trigger on auth_user that makes every password hash unusable (DISABLE_REGULAR_LOGIN only hides the form; Basic auth and /api/token/ would stay open), an inactive placeholder account so the fresh-install signup never opens, the access group created once with a regular-user role; `/accounts/oidc` and allauth's headless provider endpoints gated; admin_<id> = superuser/staff synced at login; 12 h sessions), gitea (`gitea-migrate` creates the locked break-glass admin so the first SSO user isn't auto-admin; `gitea-auth` writes the OAuth2 source with psql `\getenv`, not the CLI's argv `--secret`; required groups claim = access group, AdminGroup = admin group; password form, basic auth and passkey off; `ACCOUNT_LINKING=disabled`), mealie (`mealie-init` = guard.py: Mealie's db init, then a users trigger: every account OIDC (closes the password API and the seeded admin), username/email fixed, emails must contain `@` and never equal another account's username (Mealie matches preferred_username against the email column too); the healthcheck runs `guard.py --check`; `OIDC_NAME_CLAIM` = preferred_username because Keycloak omits `name`), matrix (`synapse-start.py` renders homeserver.yaml into a tmpfs at every start: password login and registration off, `attribute_requirements` on the groups claim, `allow_existing_users` false, `session_lifetime` 7d, server_name pinned (manifest `hosts.immutable: [matrix]`, schema + validate.py `IMMUTABLE_HOSTS`: chosen at instance creation, the Hub's SetHosts refuses to change it (409)); `synapse-init` chowns /data only while it isn't 991's). Each re-applies the instance hostname at every start. Pi-hole runs without its password only behind `FTLCONF_webserver_acl` = Traefik + loopback and `FTLCONF_webserver_domain` = its host (validate.py); AdGuard keeps its password (no web allowlist upstream)
- Guacamole: the built-in administrator is renamed `guacadmin-${GUACAMOLE_ADMIN_SUFFIX}` (generated) at DB init, and the Tomcat RewriteValve 403s X-Forwarded-User `^guacadmin` (case-insensitive; e2e `refused_users: [guacadmin-x]`). Jellyfin: `jellyfin-plugin` (plugin.py, stdlib) installs the SSO plugin pinned by version + sha256 before Jellyfin starts (no catalog, no pip); `jellyfin-setup` (setup.py, stdlib urllib) configures it and moves the local admin to the plugin's auth provider (no password login), later runs use its API key in the config volume. Vaultwarden runs `SSO_ONLY`
- CloudBeaver: automatic server configuration (CB_SERVER_* / CB_ADMIN_*, admin `cbadmin-${CLOUDBEAVER_ADMIN_SUFFIX}` + CLOUDBEAVER_ADMIN_PASSWORD, both generated) so nobody gets the setup wizard; cloudbeaver-gate 403s X-Forwarded-User `^cbadmin` (case-insensitive; e2e `refused_users: [cbadmin-x]`) and is healthy (= routed by Traefik) only while serverConfig says configurationMode false + anonymousAccessEnabled false; one-shot `cloudbeaver-config` (pinned python, JSON edit, fails closed) seeds `.data/.cloudbeaver.runtime.conf` before the first start and re-applies reverseProxy/X-Forwarded-User + anonymous off before every start (CloudBeaver 26.2 reads only that file, no GlobalConfiguration). Never weaken hardening (setup wizards, auto-provisioning, ACLs, password logins) to get a test green
- Gated backends (validate.py `GATED_BACKENDS`: esphome, zigbee2mqtt, motioneye images): apps with no access control of their own (or only a second-step login) stay on the instance's `default` network only (no traefik labels, no host networking, a `default`-only `<app>-internal` alias); the only routed service is the nginx gate running `./templates/<id>/gate.sh` (byte-identical in every template, `check_cross`) with `PORTCULLIS_TRAEFIK_IP`, `cap_drop: [ALL]` (cap_add only a subset of CHOWN/SETGID/SETUID; backends matched by image repository, any registry/mirror prefix): `allow ${ip}; deny all;`, no realip module, and it never forwards the Portcullis session (Authorization, X-Forwarded-Access-Token, X-Auth-Request-Access-Token, `_oauth2_proxy*` / `__Host-portcullis_ext*` cookies; a Cookie header it can't fully strip = 400). motionEye: `motioneye-init` (REQUIRED_INIT_JOBS) gives the empty-password admin/user accounts generated passwords, the gate waits for motionEye `service_healthy` and has its own healthcheck (empty-password logins 401). A bundled `eclipse-mosquitto` (`check_mosquitto`) depends on `mosquitto-init` (service_completed_successfully, hashed password file + ACL) and mounts a conf with `allow_anonymous false` + a password file; zigbee2mqtt's ACL gives the `homeassistant` user a reviewed allowlist only (validate.py `HA_ACL_ALLOWED` / `check_ha_acl`: exactly those lines, no pattern or pre-user topic lines, no write under `zigbee2mqtt/bridge/` but `request/permit_join`, no wildcard at/after the bridge level; Z2M lowercases bridge request keys, so writes are never denylisted): discovery, `zigbee2mqtt/+` and `+/+` state (with read denies for the two-level bridge topics HA doesn't use, `HA_ACL_BRIDGE_DENY` = logging, extensions, converters, definitions, health — all required with `+/+`: logged payloads, JavaScript source; explicit reads for bridge state/info/devices/groups/event), availability, actions, `<name>[/<endpoint>]/set|get`, `bridge/request/permit_join` — never other bridge requests (OTA updates included) or responses; `Z2M_ONBOARD_NO_SERVER: "1"`, no `ZIGBEE2MQTT_CONFIG_FRONTEND_HOST` (DEFAULT_CREDENTIAL_RULES; absent values checked via `MISSING`); external JS off by default. `TestGatedHomeTemplates` deletes each guard line of the real templates and expects a failure
- Firefox Sync (`firefox-sync`): `auth.method: custom` without `native_login` (Mozilla accounts are a vendor account system, like plex.tv): Firefox's Sync/tokenserver requests are anonymous (no cookie, no client certificate), so any gateway in front breaks it; public@file, `rate-limit@file`, `/1.0/` (tokenserver) `rate-limit-auth@file`. Who syncs = the Allowed accounts setting (Mozilla account uids; planned: ids each access-group member enters on their People page): `firefox-sync-init` (pinned psql, `guard.sql`, `\getenv`, one transaction, fails closed) writes them into firefox-sync's `sync_allowed_accounts` table and installs a `users` trigger that raises for unlisted uids (stricter than firefox-sync's own RETURN NULL trigger; empty = nobody), deletes removed uids' rows, sets the node's capacity to the maximum and recounts its load (refused tries inflate it), creates the app role; the public `firefox-sync` connects as `firefoxsync_app` (no table owner, no superuser; users read/insert + update of generation / keys_changed_at / replaced_at only, nodes only the load columns, services / migration record / allowlist read-only, no sequence privilege (identity columns); no INIT_NODE_URL on it; an event trigger refuses any object it creates — it keeps schema CREATE only for diesel's no-op `CREATE TABLE IF NOT EXISTS`), runs no tokenserver migrations and starts only after the init (validate.py `REQUIRED_INIT_JOBS` + `REQUIRED_BEFORE_ROUTED`); migrations in the unreachable `firefox-sync-migrate` as the owner (same image). No LLDAP mapping is possible (Firefox can't use another IdP); firefox-sync's self-hosted accounts (fxa-mono: SMTP, MySQL, Redis, 3 more public hosts, its own password login) are deliberately not part of this template
- Vikunja: OIDC only (`VIKUNJA_AUTH_LOCAL_ENABLED: "false"` = no password, sign-up, reset or invite-link routes; validate.py), accounts on issuer + sub, `EMAILFALLBACK`/`USERNAMEFALLBACK` never true (validate.py), `VIKUNJA_OUTGOINGREQUESTS_ALLOWNONROUTABLEIPS: "false"` (validate.py), refresh sessions end after 24 h idle (an active one keeps refreshing; `vikunja user change-status` ends it within 10 min); no group restriction upstream, so `keycloak_access_role: true` (e2e `expected_fail.outsider`); no admin mapping (instance admin is a paid, CLI-only feature); no team sync (needs a custom `vikunja_groups` claim)
- Admin panels on a path behind forward-auth go in `auth.admin_paths` (e.g. vaultwarden `/admin`) so group-gate requires `admin_group` there
- No `ports:` / `build:` / `container_name:` / `env_file:` in compose; host ports go in manifest `ports:`
- After changing manifests, regenerate docs: `python3 scripts/generate-app-docs.py --source /Volumes/workspace/portcullis/portcullis-templates` (from portcullis-docs repo)
