# Portcullis Templates — Claude Code Instructions

## Project Overview

Default app marketplace for Portcullis. Contains 51 app templates with manifest.yaml + compose.yml.

## Layout & tooling

- `schema/manifest.schema.json` — manifest JSON Schema (2020-12); keep in sync with the Hub's `validateManifest` and the docs manifest reference
- `tests/validate.py` — schema + repo rules (run `python3 tests/validate.py`; needs `tests/requirements.txt`). keep its lists in sync with the Hub's (a template CI accepts must not be skipped by the Hub); `check_traefik_routes` mirrors ParseRoutes' stricter refusals (automatic-name look-alikes `-portcullis-`, a Traefik service or HTTP router on two compose services, Traefik-enabled services whose names normalise alike, `traefik.enable` exactly true/false, enabled without a router) and `check_layout` the Hub's `CheckIDShape`; PyYAML gaps refuse more, never less); file sharing (`TestFileSharing` ports the Hub's `filesharing_test.go` / `filesharing_vars_test.go` / `routerless_test.go` rows): `person_secret` / `person_id` only on router-less custom templates (zero HTTP routers, `group_access` + `access_group`, no `native_login` needed; - Every manifest has `links: {website, source}` (schema: both required, https only; `source: null` only with `source_note`, closed source: plex). website = the project's own homepage (its docs site or repo if it has none: motioneye, scrutiny, vaultwarden); source = the canonical upstream repo root (GitHub/GitLab/Codeberg/Gitea/SourceHut), or the repo the image is built from with the upstream named in `auth.notes` (firefox-sync: porelli/firefox-sync, upstream mozilla-services/syncstorage-rs). validate.py `check_links` (`SOURCE_HOSTS` repo-root paths, `LINK_FORBIDDEN_HOSTS` registry pages, Craft `CRAFT_REPO` = source) checks the form only: verify URLs by hand (gh api repos/<o>/<r> for renames, e.g. OxiCloud → AtalayaLabs). The docs generator renders them ("Website · Source code" on each app page, columns in the catalog); the Hub ignores them
- Compose files use `portcullis-proxy` external network (NOT `portcullis`)
- Frontend services: `networks: [default, portcullis-proxy]`
- Internal services (DBs, Redis): default network only
- Header-auth apps must accept identity headers (X-Forwarded-User etc.) only from Traefik: use the app's proxy allowlist with `${PORTCULLIS_TRAEFIK_IP:-172.31.250.2}` (core var, Traefik's static IP on portcullis-proxy). The only addition: an `identity_headers` AI companion's trust network (an internal project network whose only other member is the companion; grafana trust.sh reads its subnet at start), never portcullis-proxy's subnet or a pinned IP (multi templates, G48). If the app has no allowlist, reject the header from other peers in the app's own web server (Firefly, Guacamole) or keep the app off portcullis-proxy behind a gate (CloudBeaver). Never trust `**` / `0.0.0.0/0`. Tests use `assert_traefik_only_trust` / `assert_spoofed_identity_rejected` (tests/lib.sh)
- Identity = LLDAP username, never email (core 427c0aa): LLDAP lets users edit their own email, Keycloak marks it unverified (`email_verified=false`), group-gate sends `X-Forwarded-User` = username and `X-Forwarded-Email` = email (display/notifications only). Header-auth apps key on X-Forwarded-User; OIDC apps key on `sub`/`preferred_username` and must never link accounts by email (Vaultwarden `SSO_SIGNUPS_MATCH_EMAIL: "false"`, GitLab `omniauth_auto_link_user = false`, LiteLLM email attribute → unsent claim, Immich `immich-lock-local-users`, Headscale `email_verified_required: true`). Apps that reject `email_verified=false` but accept it absent set `keycloak_clients[].email_verified_claim: false` (Hub attaches core's `email-unverified` scope instead of `email`) and must not request the `email` scope (Keycloak: `invalid_scope`; validate.py checks `*SCOPE*` env); only Vaultwarden needs it (checked upstream: Immich, GitLab, LiteLLM, Actual, Headscale, NetBird don't gate on the claim). Gates that reject foreign X-Forwarded-User must reject X-Forwarded-Email too. validate.py `IDENTITY_*` tables (and `REQUIRED_INIT_JOBS`: immich-lock-local-users, paperless-init, mealie-init, oxicloud-init, homeassistant-init, mattermost-init, firefox-sync-init; `IMAGE_ENV_REQUIRED` / `IMAGE_MANIFEST_REQUIRED` for per-image settings) enforce this; add new apps' settings there
- Template contract v2 (contracts §3.1): every manifest sets `instances: multi` (`single` only for host-level uniqueness, with the reason in `auth.notes`; none today). Host-level resources are per instance: netbird's coturn keeps host networking but reads its STUN/TURNS ports and relay range from the manifest `ports:` (validate.py: a multi template's `network_mode_host` port keys must be used in compose), scrutiny gets only the disks listed in its Disks setting (a `list`, `max_items: 8`, indexed env delivery `SCRUTINY_DISK_{n}`; motioneye's cameras the same with `MOTIONEYE_VIDEO_{n}`) as `devices:` (`:r`) with SYS_RAWIO (+ SYS_ADMIN via an enum for NVMe) instead of `privileged` (refused for multi). - Volumes: `multi` templates declare no `name:` (the Hub's override names the default instance's `portcullis_<key>` — today's names — and others `portcullis_<id>-<key>`); `single` ones declare exactly `name: portcullis_<key>`. Never rename a volume key: it is the default instance's data volume name
- Files shipped with a template are mounted read-only as `./templates/<app-id>/<file>:<path>:ro` (every instance shares them) — relative paths resolve against the core checkout on the host, and the Hub copies the template dir to `<core>/templates/<app-id>/` before every `compose up` (CI copies this repo there). Never `./<file>` directly.
- Do NOT reference `./scripts/`. From `./certs/`, only `./certs/ca-bundle.crt:<path>:ro` may be mounted (the Hub-provided CA bundle); nothing else under `./certs/`
- Every `${VAR:?...}` (required) var in a compose file must be either a core var (e.g. `PORTCULLIS_DOMAIN`) or listed in the manifest `env:` with `generate: random` — the Hub only writes those into the per-app .env (tests/lib.sh mirrors this in CI)
- Images: explicit version tag + `@sha256:` index digest, never floating tags; don't bump DB majors; keep multi-image apps in lockstep (netbird management/signal, immich server/ML, guacamole/guacd) and note upstream upgrade paths in `auth.notes`
